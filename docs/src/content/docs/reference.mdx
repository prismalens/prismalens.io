## Commands

PrismaLens has five commands: `up`, `pair`, `reset`, `doctor` and `upgrade`.
`prismalens` and `pl` are the same binary.

### `pl up`

Starts the app: the API and the web UI on one port, backed by SQLite. A new
workspace serves on port 6473. The
port lives in `<workspace>/instance.json`; `--port` or `PRISMALENS_PORT`
overrides it for one run. On Linux and macOS, a foreground `pl up` suggests
`pl service install` for a machine that should always be on.

| Flag | Default | What it does |
| --- | --- | --- |
| `--port <port>` | `6473` | Port to listen on. |
| `--host <host>` | `127.0.0.1` | Address to bind. Anything other than loopback makes the app reachable from your network and prints a warning. |
| `--workspace <dir>` | `~/.prismalens` | Folder for the database, secrets, logs, mirrors and runs. |
| `--verbose` | off | Stream every log line to the terminal. By default only warnings and errors appear. |
| `--no-open` | opens | Print the pairing link without opening a browser. |
| `--tailscale-serve` | off | Publish the app on your tailnet over HTTPS with `tailscale serve` and allow its name for this run. |
| `--telemetry=off` | unset | Turn off opt-in usage telemetry for this run regardless of Settings. See [Usage telemetry](/trust/#usage-telemetry). |

### `pl pair`

Prints a one-time pairing link for a running `pl up`. It works once, for 15
minutes. `pl pair --address <url>` checks the address first and refuses when it's
unreachable, when the host isn't allowed (it prints the
`PRISMALENS_ALLOWED_HOSTS=<host>` line to add), or when another PrismaLens
answers. Devices are named `<link label> · <browser> on <OS>`, e.g. "This
machine · Firefox on Linux". A paired device stays valid until revoked (the
cookie renews on use). See [Opening it from other devices](/guides/devices/).

| Flag | Default | What it does |
| --- | --- | --- |
| `--tailscale` | off | A link on this machine's tailnet HTTPS address; sets up `tailscale serve` for the running server if missing. |
| `--address <url>` | `http://localhost:<port>` | The address the other device will open, such as a reverse proxy. Prefer `--tailscale`. |
| `--label <name>` | none | A name shown under **Settings → Devices** until the device sends its own. |
| `--operator` | off | A link for the host's own browser, which may also pair and revoke devices. |
| `--workspace <dir>` | `~/.prismalens` | The workspace `pl up` is running on. |

### `pl reset`

Deletes the workspace: the database, secrets, logs and runs. Stop `pl up`
first. It asks before deleting (`--yes` skips the question), and it refuses a
folder that has no `prismalens.db`. `--workspace <dir>` picks another workspace.

### `pl doctor`

Checks the machine `pl up` will run on and exits non-zero if a hard check
fails. It checks the Node version, that the workspace folder is writable,
which coding agents are on `PATH`, which one would be picked, whether each
installed agent answers, where the webhook token file is, and the host and
port. `pl doctor` prints the webhook URL Alertmanager should use and whether
other machines can reach it (loopback bind = only this machine). For each agent
it prints the path the binary was found at, or the `PATH` it searched. It never
prints the token. It also prints the version and how it was installed, and
lists every `pl` on `PATH`. `--workspace`, `--port` and `--host` check the
values `pl up` would get with the same flags.

### `pl upgrade`

Upgrades PrismaLens the way it was installed: npm, the installer, Homebrew or
Scoop. `--check` only says whether a newer version exists; `--version <v>`
installs that version. See [Upgrade](/install/#upgrade).

## Environment variables

Flags on `pl up` set `PRISMALENS_PORT`, `PRISMALENS_HOST`, `PRISMALENS_WORKSPACE_DIR` and `PRISMALENS_TELEMETRY`. The rest have no flag.

| Variable | Default | What it does |
| --- | --- | --- |
| `PRISMALENS_PORT` | `6473` | Same as `--port`. Overrides `<workspace>/instance.json` for one run. |
| `PRISMALENS_HOST` | `127.0.0.1` | Same as `--host`. |
| `PRISMALENS_WORKSPACE_DIR` | `~/.prismalens` | Same as `--workspace`. |
| `PRISMALENS_TELEMETRY` | unset | `off` forces usage telemetry off for the process regardless of Settings (also accepts `0` or `false`). Set by `--telemetry=off`. Also honours `DO_NOT_TRACK` and `CI`. See [Usage telemetry](/trust/#usage-telemetry). |
| `PRISMALENS_UPDATE_CHECK` | unset | `off` turns off the daily GitHub Releases update check. Also turned off by `DO_NOT_TRACK` or `CI`. See [What leaves your machine](/trust/#what-leaves-your-machine). |
| `DO_NOT_TRACK` | unset | Standard cross-vendor variable. Any value other than `0`, `false` or `off` turns off both usage telemetry and the update check. See [Usage telemetry](/trust/#usage-telemetry). |
| `PRISMALENS_HARNESS` | unset | Pin a coding agent by id: `opencode`, `claude-code`, `codex`, `gemini`, `deepagents`. |
| `PRISMALENS_DISPATCH_CONCURRENCY` | `3` | How many investigations run at once. |
| `PRISMALENS_ALLOWED_HOSTS` | loopback and IP addresses | Hostnames the app answers to. Set it when you reach the app by a name, such as `prismalens.local`. |
| `PRISMALENS_PUBLIC_URL` | derived from host and port | The URL people open. Set it to the `https://` address of a TLS proxy in front of `pl up` so the session cookie is marked `Secure`. |
| `PRISMALENS_PROTOCOL` | `http` | `https` makes `pl up` serve TLS itself. |
| `PRISMALENS_ALERT_FLAP_WINDOW_MINUTES` | `15` | An alert that fires again within this many minutes of resolving reopens instead of starting a new episode. |
| `PRISMALENS_LOG_LEVEL` | `info` | `debug`, `info`, `warn` or `error` for the log file. |

## Limits

| Limit | Value |
| --- | --- |
| Agent start-up | 2 minutes |
| One investigation | 15 minutes, then the agent is stopped |
| Investigations at once | 3, set by `PRISMALENS_DISPATCH_CONCURRENCY` |
| Webhook deliveries | 20 per second and 600 per minute. Over the limit a delivery gets `503` with `Retry-After`, which Alertmanager retries. |
| Investigations per incident | One at a time. Investigate on an incident whose investigation is pending or running returns that investigation and starts nothing new. |

## Messages to an investigation

`POST /api/investigations/{id}/messages` with `{"text": "...", "mode": "queue" | "now"}`
answers `202` with one of these states:

| State | When |
| --- | --- |
| `queued` | The run is live; the agent reads it at its next pause. |
| `sent` | The run is live and `mode` was `now`; the agent's current step was stopped to read it. |
| `resumed` | The run had finished; the same agent session was reopened to answer it. |

It answers `409` with one of these messages:

| Message | Why |
| --- | --- |
| `The run ended before your message reached it.` | A live run finished while the message was on its way. |
| `A follow-up is already running.` | Two follow-ups were sent to a finished run at once; one of them runs. |
| `<Agent> can't reopen a finished session, so a new run starts from the report.` | The run's agent cannot continue a finished run (see [Coding agents](/coding-agents/)). |
| `This run's agent kept no session to reopen.` | The run finished before PrismaLens kept session ids, or its agent never opened one. |
| `<Agent> is no longer installed.` | The run's agent is not on `PATH` any more. |
| `This run recorded no workspace.` | The run failed before its code was cloned. |

## Answering an ask

`POST /api/investigations/{id}/asks/{askId}` with `{"decision": "approve" | "deny"}`
answers an agent's permission request and returns the outcome, for example
`{"outcome":"denied"}`. It answers `409` with this message when the ask is not
waiting, which includes a second answer to the same ask:

| Message | Why |
| --- | --- |
| `This ask is no longer waiting: it was answered, timed out, or the run ended.` | The ask was already answered, the 10-minute window passed, or the run ended. |

## Permission mode defaults

Each agent starts in its own asking mode. For OpenCode that is `build`; it was
`plan` before. See [Permission modes and asks](/coding-agents/#permission-modes-and-asks)
for every agent.

## Instance identity

`GET /api/instance` is public and returns `{instanceId, version, apiVersion}`. Launchers and `pl pair` check it to confirm a port belongs to this workspace before sending credentials or minting links.

## Known limits

- Runs on macOS, Linux and WSL2. Native Windows is a preview: it installs and runs, and CI checks it on every change, but expect rough edges.
- One `pl up` per workspace folder. A second one on the same folder refuses to start and names the process holding it.
- The desktop app attaches to a running PrismaLens on the workspace, else starts the installed service, else runs its own on the workspace's port. It shows a dialog instead of quitting when its PrismaLens stops.
- Every run keeps its transcript under `runs/<id>/`. The repository clone is deleted when the run ends; delete old transcripts by hand when you need the space.
- Installing needs a prebuilt `better-sqlite3` for your platform, or Python 3 and a C++ toolchain to build it.

## Troubleshooting

Logs are in `~/.prismalens/logs/`. Start with `pl doctor`.

**`Harness available` fails.** No known coding agent is on `PATH`. Install one
from [Coding agents](/coding-agents/), open a new terminal so `PATH` updates,
and run `pl doctor` again.

**An agent is on `PATH` but not picked.** With nothing pinned, PrismaLens picks
the first agent on `PATH` in this order: OpenCode, Claude Code, Codex, Gemini
CLI, deepagents. Pin another with `PRISMALENS_HARNESS=<id>` or in
**Settings → Agent**.

**`Harness ACP handshake` is not `answers ACP`.** The line shows the agent's own
error. Usually it is not signed in: set its provider key and restart `pl up` so
the key is in the agent's environment.

**Doctor said `answers ACP` but the run failed "not signed in".** Some agents
only check sign-in when the first investigation starts. Set the provider key
and run again.

**The service shows a git error.** It is git's message, word for word. Check
that `git clone <the same URL>` works in your terminal. A clone that needs a
password fails straight away, because PrismaLens never lets git prompt.

**The report says the run was unmapped.** The incident has no service, or the
service has no repository. Set the service's Repository field and run again.

**A run failed.** The incident shows the error and the transcript
path, `~/.prismalens/runs/<id>/transcript.jsonl`. If `pl up` was stopped
during a run, that run is marked failed when the app starts again.

**Filing a bug.** Include the output of `pl doctor` and `pl --version`, and
the relevant lines from the newest file in `~/.prismalens/logs/`. Open it at
[github.com/prismalens/prismalens/issues](https://github.com/prismalens/prismalens/issues).
