---
title: Coding agents
description: Which coding agents PrismaLens can drive, how it picks one, and how the agent signs in.
---

PrismaLens does not include a model or an agent. It drives a coding agent that
is already installed on your machine, and that agent does the reading, the
commands and the reasoning. PrismaLens talks to it over the
[Agent Client Protocol](https://agentclientprotocol.com) (ACP), the same way an
editor does.

## Supported agents

| Agent | Command PrismaLens looks for | Install | Tested with | Continue a finished run |
| --- | --- | --- | --- | --- |
| OpenCode | `opencode` | `curl -fsSL https://opencode.ai/install \| bash` or `npm i -g opencode-ai` | 1.18.30 | Yes |
| Claude Code | `claude-agent-acp` | `npm i -g @agentclientprotocol/claude-agent-acp` | 0.81.1 | Yes |
| Codex | `codex-acp` | `npm i -g @agentclientprotocol/codex-acp` | 1.13.1 | Yes |
| Gemini CLI | `gemini` | `npm i -g @google/gemini-cli` | — | Yes |
| deepagents | `dcode` | `uv tool install -U deepagents-code --with deepagents-acp` | 0.1.75 | Not yet |

**Tested with** is the version that completed an unattended investigation in
PrismaLens's CI: it started in the right folder, finished on its own and
returned a valid report. A dash means no such run yet; the agent is still
supported and selectable.

**Continue a finished run** means a message typed under a finished
investigation reopens the same agent session: the agent keeps its whole
conversation, and its code is rebuilt at the commits the run read. The answer
appears in the conversation; the report, the incident and any Slack or GitHub
delivery stay as they were. With an agent marked **Not yet**, the box starts a
new investigation instead and says why.

Each agent runs with its own behaviour and permissions, as it would in your
terminal. PrismaLens drives it; it does not make it safe. See
[Trust](/trust/) for what PrismaLens does and does not limit.

## What an agent reads from the incident's repo

An investigation runs the agent in a copy of the incident's repo. A repo can
carry configuration for coding agents: settings, hooks, MCP servers, context
files. That repo is input to the investigation, not something you chose to
trust, so PrismaLens turns off what each agent lets it:

| Agent | Repo configuration |
| --- | --- |
| Claude Code | Your own `~/.claude/settings.json` applies (`settingSources: ["user"]`). The repo's project settings, hooks and `CLAUDE.md` stay off. |
| OpenCode | Not loaded. The repo's `opencode.json` is ignored. |
| Gemini CLI | Not loaded. The repo is an untrusted folder (`GEMINI_CLI_TRUST_WORKSPACE=false`), so `.gemini/settings.json`, `.env` files and `GEMINI.md` are ignored. |
| deepagents | MCP servers are not started (`--no-mcp`). |
| Codex | Loaded as in your terminal. PrismaLens turns nothing off. |

Your own configuration for the agent is untouched either way. For Claude Code that means your allow and deny rules, sandbox setting, hooks and `env` in `~/.claude/settings.json` apply, as they do in your terminal.

## How PrismaLens chooses

1. `PRISMALENS_HARNESS`, if you set it when starting `pl up`. For example `PRISMALENS_HARNESS=claude-code pl up`.
2. Otherwise the agent chosen in **Settings → Agent**.
3. Otherwise the first agent in the table above that is on your `PATH`.

If none of these finds an agent, Settings says **No investigation agent is
available on this machine**, and `pl doctor` lists the install commands above.

## Signing the agent in

The agent uses its own configuration and sign-in, as it would in your terminal:
`claude /login`, `codex login`, `gemini` and `opencode auth login` carry over.
Or put the provider key (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`,
`GEMINI_API_KEY`) in the environment you start `pl up` from. PrismaLens passes
only the variables that agent reads and does not read, copy or store the login.
Your use of an agent is governed by your agreement with its provider. Then check:

```text
$ pl doctor
✔ Harness ACP handshake: OpenCode: answers ACP
```

`answers ACP` means the agent started and replied. It does not prove the agent
is signed in: some agents only check that when the first investigation starts.
The other results are `sign in needed`, `no answer in 10s` and
`failed to start`, each with the agent's own message.
**Settings → Agent → Check readiness** runs the same check from the app.

The agent does not inherit your whole environment. See
[Credentials](/trust/#credentials).

## Permission modes and asks

Each agent has its own permission modes, and the one a run starts in decides
what the agent asks about. PrismaLens never answers an ask for you. Pick the
mode in **Settings → Agent → Permission mode** (saved per agent) or from the
mode chip under the composer. The chip lists the agent's own mode names.

| Mode | Claude Code | Codex | Gemini CLI | OpenCode |
| --- | --- | --- | --- | --- |
| Supervised (the default) | `default` (Manual) | `read-only` ("Ask for approval") | `default` | `build` |
| Auto-accepts edits | `acceptEdits` | `workspace-write` (2.x only) | `autoEdit` | Not offered |
| Auto | `auto` | `agent` | Not offered | Not offered |
| Full access | `bypassPermissions` | `agent-full-access` | `yolo` | Not offered |

Codex 1.13.1, the tested version, offers "Ask for approval" (`read-only`),
`agent` and `agent-full-access`. The auto-accepts-edits mode exists on Codex 2.x
only.

The default mode does not mean every call asks. Which calls ask is the agent's
own rule, the same as in your terminal:

| Default mode | Asks before | Runs without asking |
| --- | --- | --- |
| Claude Code `default` (Manual) | Edits and shell commands | Reads, and whatever your `~/.claude/settings.json` allows |
| Codex `read-only` ("Ask for approval") | Going past its sandbox, such as network access or a write outside the snapshot | Reads, and edits inside the snapshot |
| Gemini CLI `default` | Edits and shell commands | Reads |
| OpenCode `build` | Whatever your `opencode.json` sets to `ask`. By default that is files outside the workspace only. | Everything else, including edits and commands inside the snapshot |

The other modes ask less:

- **Auto-accepts edits.** Claude Code's `acceptEdits` takes file edits, and file commands such as `mkdir`, `mv` and `cp` inside the snapshot, without asking. Gemini CLI's `autoEdit` takes file edits without asking. Both still ask before other shell commands.
- **Auto.** Claude Code's `auto` lets a classifier decide most calls without asking. Codex's `agent` works in Codex's sandbox with no network.
- **Full access.** Codex's `agent-full-access` never asks and runs outside Codex's sandbox. Gemini CLI's `yolo` runs every call without asking. Claude Code's `bypassPermissions` skips almost every prompt.

On Claude Code, a deny rule in your `~/.claude/settings.json` refuses the call
without asking, in every mode.

There is no plan mode. Plan modes are never offered and no run starts in one. A
plan mode stored from an earlier version reads as the default mode.

When the agent asks, the run waits:

- The Conversation shows a card naming the call, with **Approve** and **Deny**. Deny refuses the call and the run goes on to its report.
- The board, the sidebar run row and the incident band say **Waiting for your approval**.
- The desktop app raises a notification, "INC-12 is waiting for your approval", and a click opens that run.
- The ask survives a reload.

An ask nobody answers is denied after 10 minutes, and the card reads "No one
answered in 10 minutes, so it was denied". The window never outlives the run: it
ends a minute before the run's 15-minute limit. When it is shortened, the card
says "The run's time limit is near, so this ask expires at 14:09:30", and then
"Denied: the run's time limit was reached". Stopping the run denies a waiting ask
too, and so does a restart of PrismaLens.

Here is one ask, from Claude Code in Manual mode:

```text
Settings → Agent: Claude Code, Permission mode: Manual
14:02:11  the agent asks to run "Write /tmp/pl-walk-write.txt"
          the card shows Approve and Deny, expiring at 14:12:11
          the board, sidebar and band say "Waiting for your approval"
          the desktop app notifies "INC-12 is waiting for your approval"
14:03:40  you click Deny
          the agent is told the call was refused
          the card reads "You denied it", and the agent goes on to its report
```

If nobody had answered by 14:12:11, the card would read "No one answered in 10
minutes, so it was denied". A second answer to the same ask gets
`409`; see [Reference](/reference/#answering-an-ask).

## Choosing a model

Each agent has its own default model. To use a different one, click the model
next to the agent picker, under the composer or in **Settings → Agent**, and
type an id in that agent's own format. It is sent exactly as typed, and it is
kept per agent: a model you set for Claude Code never reaches OpenCode.

The list under the field is a suggestion. Once you click **Check readiness** on
an agent that offers its own list, that list is shown; otherwise PrismaLens
shows its bundled model catalogue. An id missing from the list is noted ("sent
as typed"), never refused.

Codex, Gemini CLI and deepagents take no model setting. A model stored for one
of them stops the next run before it starts, with the reason in **Settings →
Agent** and on the Investigate button. For those agents the model pill offers
only **Clear model**.

### Custom models

PrismaLens never probes your agent's endpoint, so the list shows only what the
agent reports. To use a model your endpoint serves that the agent does not list,
add its id in **Settings → Agent → Custom models** with **Add custom model**.
Removing one asks for confirmation. Added ids show in the picker as "Added by
you". A run on one that the endpoint does not serve fails.

On Claude Code an added model reaches the agent through
`ANTHROPIC_CUSTOM_MODEL_OPTION`, set when the agent starts. When your
environment names the model with `ANTHROPIC_MODEL`, the Agent default row reads
"`<model>`, from your environment".

Upgrading from 0.5.0 drops the single shared model setting. Enter the model
again for each agent that needs one.

### Correcting the catalogue between releases

PrismaLens never downloads a catalogue. To correct one before the next release,
put a `model-catalogue.json` in the workspace folder. It replaces the bundled
one only if its `updatedAt` is newer; a file that fails to parse is ignored with
a warning in the log.

```json
{
  "version": 1,
  "updatedAt": "2026-10-01T00:00:00Z",
  "harnesses": {
    "claude-code": {
      "models": [
        { "id": "claude-sonnet-5", "name": "Claude Sonnet 5", "status": "current" },
        { "id": "claude-haiku-4-5-20251001", "name": "Claude Haiku 4.5", "status": "legacy" }
      ]
    }
  }
}
```

With that file in `~/.prismalens`, the Claude Code suggestions show those two
models, and Haiku is marked legacy. Delete the file to go back to the bundled
catalogue. A release whose bundled catalogue is newer than your file wins
without your deleting it.

## Follow-ups on an older run

A run keeps reasoning at the commit it was pinned to. When a newer run of the
same incident exists, an older run shows "A newer run (Run #2) looks at
`a1b2c3d`" above the box, with a link to the newer run. A follow-up on the older
run tells the agent, so it knows newer commits exist. PrismaLens does not count
them.
