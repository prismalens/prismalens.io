---
title: Coding agents
description: Which coding agents PrismaLens can drive, how it picks one, and how the agent signs in.
---

PrismaLens does not include a model or an agent. It drives a coding agent that
is already installed on your machine, and that agent does the reading, the
commands and the reasoning. PrismaLens talks to it over the
[Agent Client Protocol](https://agentclientprotocol.com) (ACP), the same way an
editor does.

## Supported agents

| Agent | Command PrismaLens looks for | Install | Tested with | Continue a finished run |
| --- | --- | --- | --- | --- |
| OpenCode | `opencode` | `curl -fsSL https://opencode.ai/install \| bash` or `npm i -g opencode-ai` | 1.18.30 | Yes |
| Claude Code | `claude-agent-acp` | `npm i -g @agentclientprotocol/claude-agent-acp` | 0.81.1 | Yes |
| Codex | `codex-acp` | `npm i -g @agentclientprotocol/codex-acp` | 1.13.1 | Yes |
| Gemini CLI | `gemini` | `npm i -g @google/gemini-cli` | — | Yes |
| deepagents | `dcode` | `uv tool install -U deepagents-code --with deepagents-acp` | 0.1.75 | Not yet |

**Tested with** is the version that completed an unattended investigation in
PrismaLens's CI: it started in the right folder, finished on its own and
returned a valid report. A dash means no such run yet; the agent is still
supported and selectable.

**Continue a finished run** means a message typed under a finished
investigation reopens the same agent session: the agent keeps its whole
conversation, and its code is rebuilt at the commits the run read. The answer
appears in the conversation; the report, the incident and any Slack or GitHub
delivery stay as they were. With an agent marked **Not yet**, the box starts a
new investigation instead and says why.

Each agent runs with its own behaviour and permissions, as it would in your
terminal. PrismaLens drives it; it does not make it safe. See
[Trust](/trust/) for what PrismaLens does and does not limit.

## Access levels

Every run has an access level. It names what the agent may touch, and
PrismaLens answers each of the agent's permission requests by it. A run
starts at **Read-only**; the two write levels are offered only after you turn
on **Allow write levels** in **Settings → Agent**.

| Level | Files | Commands | Network |
| --- | --- | --- | --- |
| **Read-only** (default) | Reads the copy | Read-only commands | `GET` requests to the telemetry addresses in the brief and no other address, with no request body |
| **Read-only with your tools** | Reads the copy | Plus the read commands of the CLIs you are signed in to: `kubectl get/describe/logs/top/explain`, `aws … describe-*/get-*/list-*`, `gcloud … describe/list`, `az … show/list`, `gh … view/list/status`, `docker ps/logs/inspect` | `GET` to any address, with no request body |
| **Edit the copy** | Writes inside the run's throwaway copy | Plus local `git` (commit, stash, checkout) and test runners | As above |
| **Full access** | Anything | Anything | Anything; PrismaLens allows every request and logs it |

The box describes Read-only in one line:

> Reads the copied code and queries the telemetry addresses in the brief.
> PrismaLens refuses writes, installs, other addresses and other ways out that
> it can see. A guardrail for an honest agent, not a sandbox.

Below Full access PrismaLens refuses, at every level: the agent's own fetch
tool; `sh -c`, `eval`, `python -c`, `node -e` and other inline programs; an
interpreter run on a file or on its input (`bash script.sh`, `python x.py`,
`source`); commands that start other commands (`find -exec`, `xargs`, `make`,
`env cmd`, `sudo`, pagers and editors); `npx`, `go run`, `git clone` and git's
remote commands; package installs; `curl` and `wget` with a request body, a
method other than `GET` or `HEAD`, a proxy, a `--resolve`, a config file or a
protocol other than HTTP; DNS and other network tools (`dig`, `nslookup`,
`ssh`, `nc`, `psql`); paths outside the copy; and credential paths such as
`.ssh`, `.aws`, `.kube`, `.netrc`, `.npmrc` and `.env`, inside the copy too.

The gate is a text rule, not a boundary. It reads each command before it runs,
so what it cannot see gets through:

- a program already in the copy run by its own name, such as `./scripts/check`;
- a file a previous allowed step wrote that a later command reads as its configuration;
- a wrapper or interpreter PrismaLens does not list.

An operating-system boundary needs Codex's sandbox or a container.

### What each agent adds

Where an agent has its own permission mode, PrismaLens sets it to match the
level, so the agent asks less. The run's report names the layer that was set.

| Agent | Read-only and Read-only with your tools | Edit the copy | Full access |
| --- | --- | --- | --- |
| OpenCode | Edits denied in its config, shell commands asked, web fetch and web search denied | Edits and shell commands asked, web fetch and web search denied | Edits, shell, web fetch and web search allowed |
| Claude Code | `default` mode | `default` mode | `bypassPermissions` mode |
| Codex | Its `read-only` mode: an operating-system sandbox with no network | Its `agent` mode: writes in the copy, no network | Its full-access mode |
| Gemini CLI | `plan` mode, when it offers one | `default` mode | `yolo` mode |
| deepagents | Nothing: PrismaLens's gate is the only layer | Same | Same |

Codex's own sandbox is the one operating-system boundary in this table. It
blocks all network, so at the read levels a Codex run cannot query Prometheus;
its report says **Codex's sandbox allows no network** under what it could not
check.

## What an agent reads from the incident's repo

An investigation runs the agent in a copy of the incident's repo. A repo can
carry configuration for coding agents: settings, hooks, MCP servers, context
files. That repo is input to the investigation, not something you chose to
trust, so PrismaLens turns off what each agent lets it:

| Agent | Repo configuration |
| --- | --- |
| Claude Code | Not loaded. Project settings and hooks stay inert (`settingSources: []`). |
| OpenCode | Not loaded. The repo's `opencode.json` is ignored. |
| Gemini CLI | Not loaded. The repo is an untrusted folder (`GEMINI_CLI_TRUST_WORKSPACE=false`), so `.gemini/settings.json`, `.env` files and `GEMINI.md` are ignored. |
| deepagents | MCP servers are not started (`--no-mcp`). |
| Codex | Loaded as in your terminal. PrismaLens turns nothing off. |

Your own configuration for the agent is untouched either way.

## How PrismaLens chooses

1. `PRISMALENS_HARNESS`, if you set it when starting `pl up`. For example `PRISMALENS_HARNESS=claude-code pl up`.
2. Otherwise the agent chosen in **Settings → Agent**.
3. Otherwise the first agent in the table above that is on your `PATH`.

If none of these finds an agent, Settings says **No investigation agent is
available on this machine**, and `pl doctor` lists the install commands above.

## Signing the agent in

The agent uses its own configuration and sign-in, as it would in your terminal:
`claude /login`, `codex login`, `gemini` and `opencode auth login` carry over.
Or put the provider key (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`,
`GEMINI_API_KEY`) in the environment you start `pl up` from. PrismaLens does not
read, copy or store the login. Then check:

```text
$ pl doctor
✔ Harness ACP handshake: OpenCode: answers ACP
```

`answers ACP` means the agent started and replied. It does not prove the agent
is signed in: some agents only check that when the first investigation starts.
The other results are `sign in needed`, `no answer in 10s` and
`failed to start`, each with the agent's own message.
**Settings → Agent → Check readiness** runs the same check from the app.

The agent does not inherit your whole environment. See
[Credentials](/trust/#credentials).

## Choosing a model

Each agent has its own default model. To use a different one, click the model
next to the agent picker, under the composer or in **Settings → Agent**, and
type an id in that agent's own format. It is sent exactly as typed, and it is
kept per agent: a model you set for Claude Code never reaches OpenCode.

The list under the field is a suggestion. Once you click **Check readiness** on
an agent that offers its own list, that list is shown; otherwise PrismaLens
shows its bundled model catalogue. An id missing from the list is noted ("sent
as typed"), never refused.

Codex, Gemini CLI and deepagents take no model setting. A model stored for one
of them stops the next run before it starts, with the reason in **Settings →
Agent** and on the Investigate button. For those agents the model pill offers
only **Clear model**.

Upgrading from 0.5.0 drops the single shared model setting. Enter the model
again for each agent that needs one.

### Correcting the catalogue between releases

PrismaLens never downloads a catalogue. To correct one before the next release,
put a `model-catalogue.json` in the workspace folder. It replaces the bundled
one only if its `updatedAt` is newer; a file that fails to parse is ignored with
a warning in the log.

```json
{
  "version": 1,
  "updatedAt": "2026-10-01T00:00:00Z",
  "harnesses": {
    "claude-code": {
      "models": [
        { "id": "claude-sonnet-5", "name": "Claude Sonnet 5", "status": "current" },
        { "id": "claude-haiku-4-5-20251001", "name": "Claude Haiku 4.5", "status": "legacy" }
      ]
    }
  }
}
```

With that file in `~/.prismalens`, the Claude Code suggestions show those two
models, and Haiku is marked legacy. Delete the file to go back to the bundled
catalogue. A release whose bundled catalogue is newer than your file wins
without your deleting it.
