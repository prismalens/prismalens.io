PrismaLens is one command under two names, `pl` and `prismalens`. Install it
one way and stick to that: every copy on a machine shares the workspace
`~/.prismalens`, and an older copy refuses a database a newer one has
upgraded.

## Install

<Tabs syncKey="channel">
<TabItem label="macOS and Linux">

```bash
curl -fsSL https://prismalens.io/install.sh | sh
```

No Node needed: the installer brings its own and checks the download against
the release's `SHA256SUMS`. `sh -s -- --help` lists its options.

</TabItem>
<TabItem label="npm">

Needs Node.js 24.

```bash
npm install -g prismalens
```

</TabItem>
<TabItem label="Homebrew">

```bash
brew install prismalens/tap/prismalens
```

</TabItem>
<TabItem label="Windows (preview)">

WSL2 with the macOS and Linux installer is the supported path. Native Windows
installs and runs, with rough edges. In PowerShell:

```powershell
irm https://prismalens.io/install.ps1 | iex
```

Scoop (preview) works too:

```powershell
scoop bucket add prismalens https://github.com/prismalens/scoop-bucket
scoop install prismalens
```

</TabItem>
<TabItem label="Desktop app (preview)">

Download the zip for your OS from the
[latest release](https://github.com/prismalens/prismalens/releases/latest). It
is unsigned, so your OS warns before opening it.

</TabItem>
</Tabs>

## Keep it running

`pl up` runs until you stop it. On Linux and macOS, `pl service install` runs
it in the background for your user and starts it when you log in. On Windows,
turn on **Start at login** in the desktop app.

`--ignore-missing` skips a file it cannot find without saying so. Go on only when
your file's name appears above with `OK`. On macOS, `shasum -a 256 -c SHA256SUMS
--ignore-missing` does the same as `sha256sum`.

The npm package is published with npm provenance. This reads the registry's
metadata and shows the attestation is there; it does not verify it:

```console
$ npm view prismalens@0.5.2 dist.attestations.provenance.predicateType
https://slsa.dev/provenance/v1
```

`npm audit signatures` does not work on a project that installed `prismalens`: it
looks up the packages bundled inside the tarball on the registry, where they are not
published, and stops with a 404.

Current releases also carry `prismalens-<version>.cdx.json`, a CycloneDX SBOM of
the installed tree; older ones do not.

## Upgrade

```bash
pl upgrade
```

It upgrades the way you installed. The desktop app shows a notification
with a download link instead. Your database upgrades itself on the next start
and is backed up first, as `prismalens.db.bak-<time>` in the workspace.

## Uninstall

Uninstalling leaves your workspace (`~/.prismalens`). To delete it as well,
stop PrismaLens and run `pl reset` first. If you installed the background service, run
`pl service uninstall` too.

| Installed with | Uninstall |
| --- | --- |
| The installer (macOS, Linux) | `curl -fsSL https://prismalens.io/install.sh \| sh -s -- --uninstall` |
| The installer (Windows) | `& ([scriptblock]::Create((irm https://prismalens.io/install.ps1))) -Uninstall` |
| npm | `npm uninstall -g prismalens` |
| Homebrew | `brew uninstall prismalens` |
| Scoop | `scoop uninstall prismalens` |
| The desktop app | delete the app |
