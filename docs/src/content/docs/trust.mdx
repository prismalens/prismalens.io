PrismaLens puts a coding agent next to your code. This page says what that
agent can reach, what PrismaLens does to limit it, and where those limits stop.

## The short version

- The agent works in a **copy** of your repository, never in your checkout.
- PrismaLens **refuses** the agent's edits, deletes and known mutating commands. That is a guardrail, not a wall.
- The agent **cannot fetch URLs**. OpenCode also cannot web-search or read outside the snapshot.
- Runs are **not sandboxed**. Nothing at the operating-system level blocks a write or a network call; the report names the mechanism a run had.
- PrismaLens sends **nothing** to us. Your agent sends your code and the alert to **its** model provider.
- PrismaLens **never** reads or stores your agent's login.
- Everything PrismaLens keeps is in **one folder**, `~/.prismalens`.

## The read-only policy

Coding agents ask their client before they act, and PrismaLens is that client.
It refuses edit, delete and move tools, and shell commands that look like
writes: redirects, `rm`, `mv`, `cp`, `chmod`, `sed -i`, state-changing git
commands, package installs, `docker`, mutating `kubectl`, `helm` and
`terraform` commands, `kill`, `wget`, and `curl` with `POST`, `PUT`, `PATCH` or
`DELETE`. Reading, searching and commands like `ls`, `grep` and `git log` are
allowed.

<Aside type="caution" title="This is a guardrail">
The shell rules match command text, so a command written to dodge them, such as
a short Python script that writes a file, gets through. The policy catches an
agent making a mistake. It does not stop an agent that was talked into
misbehaving by text it read. For a real boundary, run PrismaLens under a user
or in a VM that can read only what it should, and give the agent read-only
credentials for anything outside the copy.
</Aside>

PrismaLens refuses paths outside the snapshot, judged where they really land:
through `..`, symlinks, `~` and globs such as `cat *`. Like the rest of the
policy, it matches command text, so the agent can still read any file your user
can read if it writes a command that dodges the rules. Keep that in mind before
you run PrismaLens under an account that can read production credentials.

Agent configuration committed in the repository never reaches the agent:
before a run starts, PrismaLens removes `.claude`, `.opencode`, `opencode.json`,
`.mcp.json`, `.gemini` and `.codex` at any depth from the snapshot, so a
repository cannot bring its own tools, hooks or instructions into the run.

Alert fields reach the agent inside a block marked as untrusted data. If the
agent spots text trying to give it orders, it quotes it in the report under
**Content tried to instruct the agent**.

## What leaves your machine

- **From PrismaLens:** nothing. No analytics, no crash reports, no update check. The app listens on `127.0.0.1` unless you pass `--host`.
- **At install:** a documentation dependency of the API contains an install-time analytics package (`@scarf/scarf`). Set `SCARF_ANALYTICS=false` before `npm install -g prismalens` to turn it off.
- **From your agent:** what it reads, including source code, command output and the alert, goes to its model provider, as it would if you used the agent directly.
- **From git:** fetching a repository URL contacts that host with your git credentials.

## Credentials

| Credential | What PrismaLens does |
| --- | --- |
| Your agent's login | Never reads, copies or stores it. |
| Provider keys in your environment, such as `ANTHROPIC_API_KEY` | Passes the keys the chosen agent reads into its environment. Never stores them. |
| A gateway for Claude Code | Set `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN`; the model you set in Settings applies to every tier. The URL must be `https://` unless it is on this machine. |
| Your git credentials | Never reads them. Git uses them. |
| A GitHub token you add in Settings | Stores it encrypted and sends it only with git requests to GitHub. |
| PrismaLens's own secrets | Generated on first start, stored as owner-only files, never given to the agent. |

Apart from those provider keys, the agent gets only `PATH`, `HOME`, `USER`,
`LOGNAME`, `SHELL`, `PWD`, `LANG`, `LC_ALL`, `LC_CTYPE`, `TERM`, `TMPDIR` and
`TZ` from your environment.

There are no accounts. A browser gets in only by opening a one-time pairing
link that `pl up` or `pl pair` prints on the host; no address, `localhost`
included, grants access by itself. Only the host's own session can pair or
revoke other devices. See [Opening it from other devices](/guides/devices/).

## Where your data lives

Everything is under `~/.prismalens`, or the folder you pass to
`pl up --workspace`.

| Path | Contents |
| --- | --- |
| `prismalens.db` | Incidents, alerts, services, investigations, reports and their event streams |
| `runs/<id>/repo` | The snapshot a run read, deleted when the run ends, whatever its outcome |
| `runs/<id>/transcript.jsonl` | Raw messages between PrismaLens and the agent, kept as a best effort |
| `repos/` | Mirrors of repositories added by URL |
| `logs/` | App logs |
| `PRISMALENS_*_FILE` | Generated secrets |

To remove everything, stop `pl up` and delete the folder.

## These websites

prismalens.io and docs.prismalens.io count visits with PostHog Cloud EU, without
cookies or browser storage. They record which pages are opened and when a link to
npm, GitHub or a release is clicked, or an install command is copied. The landing
site also records where on the page people click, as a heatmap. Nothing typed
into a page is recorded, IP addresses are not stored, and a visit is never
linked to an install of PrismaLens.
