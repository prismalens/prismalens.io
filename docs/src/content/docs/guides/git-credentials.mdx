A run reads a service's code from its repository (see
[Services and their code](/guides/services/)). For a private repository git
needs a credential, and PrismaLens uses one of two:

- **This machine's own git login.** Your SSH keys for an SSH URL, or the
  credential helper your terminal's git already uses for HTTPS, such as the one
  `gh auth login` or Git Credential Manager sets up. Nothing to add: if `git
  clone` works in your terminal, it works here.
- **A git host token** you add in PrismaLens, for a host this machine's git
  cannot reach.

A public repository needs neither. A folder on this machine needs none.

## Add a token

Open **Settings → Integrations**. Under **Git hosts**, choose **Add a
token**:

| Field | What to enter |
| --- | --- |
| Host | `github.com` (the default), `gitlab.com`, `bitbucket.org`, or your own git host, with `:port` if it has one |
| Token | A token with read access to the repositories your runs read. GitHub: a fine-grained token with **Contents: read** on them. GitLab: a project or personal token with `read_repository`. Bitbucket Cloud: a repository access token with **Repository: read**. |

Each saved token is a row with its name, its status, and `github.com, fp
3f9a2c1b, added 2026-10-11`. A token reads **not tested** until a **Test** or
a clone has used it, then **connected** or why it failed. The token itself never shows again. **Test**
tries each repository that uses it and says what answered. The row's menu
edits or removes it. With no token saved, the group says "None yet. Runs
clone with this machine's own git login until you add a token for a host it
can't reach."

PrismaLens stores the token encrypted and sends it only to git, for its own
host, over HTTPS. It reaches git as an `Authorization` header set through
git's environment, never in the URL or the mirror's config, and with a token
in use your credential helpers are switched off for that call.

## Which one a clone uses

PrismaLens decides before git runs, for each repository:

| Repository | Pinned token | This machine's git has a login for the host | Saved tokens for the host | Clones with | Shown as |
| --- | --- | --- | --- | --- | --- |
| `git@github.com:acme/api.git` | any | n/a | any | your SSH keys | `machine git (ssh keys)` |
| `https://github.com/acme/api` | `ci-bot`, active | any | any | `ci-bot` | `token ci-bot` |
| same | `ci-bot`, expired or in error | any | any | nothing; the run fails until you replace it or set Auto | pinned token unusable |
| same | Auto | yes | any | your git login | `machine git (gh, sumit)` |
| same | Auto | no | exactly one (`ci-bot`) | `ci-bot` | `token ci-bot` |
| same | Auto | no | two or more | nothing until you pick one | `no token chosen` |
| same | Auto | no | none | no credential | `public` |

"Has a login" means git's credential helper answered for the host. PrismaLens
asks it the way `git credential fill` does, keeps the user name for the label,
and discards the rest. A helper that does not answer in 5 seconds counts as
no login, and the repository says "Your machine's git helper did not answer
in 5 s."

**One fallback.** When your own git login (not SSH) is refused, has no
credential, or the host says not found, and exactly one active saved token
matches the `https` host, PrismaLens tries the same call once with that token.
The run then shows the token with "(your machine's git was refused)". With
two or more matching tokens it stops and asks you to pick one.

### Pick a token for a repository

Open **Services → the service**. Each repository in **Code** says which
credential it clones with, for example `main at 3f2c9a1b04de, Code: machine git
(gh, sumit)`. When two saved tokens match its host, or once you pinned one, a
picker offers **Auto** and each token by name and fingerprint. **Auto**
follows the table above. A pin to a token you deleted, or to a token for
another host, is cleared, and the repository goes back to Auto.

## Where the app shows it

The app always says which credential cloned the code:

| Where | What it says |
| --- | --- |
| A run's transcript, in the strip under the header | `Code: machine git (gh)`, `Code: token ci-bot` or `Code: public`. Hover for "Cloned with token ci-bot, via git-host-token, fp 3f9a2c1b". |
| Run details → Summary → Code | Each repository at its commit, such as `main at 3f2c9a1`, and "Cloned with token ci-bot from https://github.com/acme/api." |
| Services → the service → Code | The repository's credential, its problem if it has one, and the picker |
| The overview's What changed card | When no credential reaches the host: "Add a git host token, or sign in to git on this machine, to see deploys and merges", with **Add a token** |

The overview's Latest run strip names the agent and model only.

## When git fails

A clone or a history read that fails says why in words you can act on:

| Message | What to do |
| --- | --- |
| `No credential for github.com. Add a Git host token in Settings → Integrations, or sign your machine's git in to github.com.` | Add a token, or sign in with your git host's CLI or credential manager |
| `github.com refused your machine's git (gh). Sign in again, or add a Git host token.` | Sign in again, or add a token |
| `github.com rejected token "ci-bot" (fp 3f9a2c1b). It was revoked or mistyped; replace it.` | Edit the token and paste a new one |
| `Token "ci-bot" expired on 2026-10-01. Replace it in Settings → Integrations.` | Replace the token |
| `Token "ci-bot" can't see acme/api: it doesn't exist or the token has no access to it. Check the URL or grant the repository on the token.` | Grant the repository on the token, or fix the URL |
| `Pinned token ci-bot is expired on 2026-10-01; replace it or set Auto.` | Replace it, or set the repository to Auto |
| `2 saved tokens match github.com. Pick the one this repository uses.` | Pick one on the repository |
| `acme/api was not found or is private. Check the URL or add a credential for github.com.` | Fix the URL, or add a credential |
| `github.com's SSH host key is not trusted yet. Run ssh -T git@github.com once as the user that runs PrismaLens, or use an HTTPS URL with a token.` | Run that once |
| `github.com refused your SSH key.` | Load the key into your SSH agent. Under the background service, which has no SSH agent, use an HTTPS URL with a token. |
| `Could not reach github.com:` and git's first line | Check the network or the host name |

Git never prompts. A call that would need a password fails at once with one of
these messages instead of waiting.

## Checking from the terminal

`pl doctor` has a **Git** check: git's version and the credential helpers this
shell would use, per host. It is required: without git, PrismaLens cannot read
a service's code.

```text
✔ Git: git 2.43.0 (for this shell); credential helpers: github.com: !/usr/bin/gh auth git-credential; all hosts: cache
```

Without git the line reads `Git: git missing: PrismaLens reads a service's
code with git. Install it and run pl doctor again`, and the required checks
fail.

<Aside type="caution" title="The background service has its own environment">
When the background service is installed, `pl doctor` adds a **Git in the
background service** line: the service runs with its own environment, so
helpers that need a desktop keyring or an SSH agent may not work there. If runs under the service fail with
"No credential" while your terminal clones fine, add a git host token.
</Aside>

## Connections from an earlier version

A GitHub App connection from 0.5.0 shows as **GitHub App (removed in 0.5.1)**
with only **Delete**: "This connection no longer works. Delete it here, then
delete the app or its private key on GitHub (Settings → Developer settings →
GitHub Apps)." Add a git host token, or sign in to git on this machine,
instead.
