---
title: When PrismaLens restarts
description: What happens to a run that was working when PrismaLens stopped, how it carries on when PrismaLens starts again, and why a run sometimes waits for you instead.
---

PrismaLens runs on your own computer, so a run can be cut off part way: the
laptop sleeps or restarts, an update installs, or the app is closed. When
PrismaLens starts again, each run whose agent was still working carries on
where it was. It continues in the same agent session, and PrismaLens tells the
agent what happened while it was away.

## What the agent is told

The resumed run's conversation shows a divider, **Stopped at 08:52, resumed at
09:14**. Under it is a message from PrismaLens, marked **PrismaLens, sent
automatically**, never as yours:

```text
PrismaLens stopped at 28 Oct, 08:52 and started again at 28 Oct, 09:14
(times UTC+1), 22 minutes later. Your last command may or may not have
completed: check before relying on its effect. While PrismaLens was stopped,
1 alert fired on this incident: CheckoutLatencyHigh at 28 Oct, 09:03. Your
workspace is at commit 4f1c2ab, as it was. Continue the investigation from
your last step.
```

The message is built when the run starts again, from what PrismaLens finds
then:

- **The gap:** when PrismaLens was last running and when it started again.
- **The last command:** the agent's last command may have been cut off, so
  the agent checks before relying on it.
- **Alerts:** the alerts on the incident that fired or resolved while
  PrismaLens was stopped. A resumed run waits about 30 seconds after the start,
  so PrismaLens can catch up on its alert sources first. If that catch-up has
  not finished, the message says that alerts from the gap may be missing.
- **Asks:** an ask that was waiting for your answer was closed unanswered.
  The agent may ask again, and the new ask waits for you as usual.
- **The workspace:** what git shows of the run's folder. It is either "as it
  was", "with 3 changed files", "at a different commit", or "rebuilt", when
  the folder was removed while PrismaLens was stopped. PrismaLens keeps a
  run's folder until its incident is resolved, so a rebuild is rare.
- **The question:** when the run was answering a question you asked, the
  message repeats the question.

The run strip reads **Resumed after PrismaLens restarted** while it works, and
the Inbox lists it under **Working** as **Resumed after a restart**.

## Which runs resume

PrismaLens tells a restart from a stop you made, and from a run that ended on
its own:

| When PrismaLens stopped, the run was | When PrismaLens starts again | The run shows |
| --- | --- | --- |
| Working | Resumed in the same session, with the message above | **Stopped at 08:52, resumed at 09:14** |
| Answering a question you asked | Resumed as the same answer; the message repeats the question | The divider, then the answer |
| Waiting for your answer to an ask | The ask is closed unanswered; the run resumes and may ask again | **Denied: PrismaLens restarted**, then the new ask |
| Started by an alert | Resumed unattended, at its own permission level; it still never asks | The divider, then the work |
| Stopped by you | Stays stopped | **Stopped by you** |
| Finished, with its report written just before the stop | Not run again | Interrupted, with Resume |
| Failed while PrismaLens kept running (the agent itself crashed) | Stays failed; this is not a restart | The agent's error |
| Queued and not started | Starts when a slot is free | Queued |
| Working, but PrismaLens was off for more than a day | Not resumed | Interrupted, the reason, **Resume** |
| Working, and PrismaLens stopped during each of its last 3 resumes | Not resumed | Interrupted, the reason, **Resume** |
| Working, but its agent can't start (not installed, signed out, model refused) | Not resumed | Interrupted, the reason, **Resume** |
| Working, and the agent from before the stop may still be running | Not resumed; a second agent is never started on the same session | Interrupted, the reason, **Resume** |
| Working, with **Resume after a restart** turned off | Not resumed | Interrupted, the reason, **Resume** |

Closing the app is a restart, not a stop: a run you didn't stop resumes. If
PrismaLens starts again less than 2 minutes after a start that resumed runs,
it resumes none. A run that keeps stopping PrismaLens is not tried forever.

When the computer only sleeps and PrismaLens keeps running, nothing is
resumed: the agent carries on when the computer wakes.

Resumed runs wait for a free slot like any other run, so many at once start a
few at a time.

## A run that was not resumed

The run page reads **Interrupted (PrismaLens restarted)** with the reason, for
example "Not resumed: Codex isn't signed in on studio-mac. Sign in there, then
resume." **Resume** sends the same message an automatic resume would, recorded
as **sent when you pressed Resume**. You can also send a message below, with
any agent, as on any finished run.

## The notice

The first time you open PrismaLens after a start that resumed runs, from any
device, a notice says what happened. For example: **PrismaLens started
again**, "It stopped at 08:52 and was off for 22 minutes.", **3 investigations
resumed**, **1 couldn't: INC-41, Codex isn't signed in**, and **Open INC-41**.
Dismissing it hides it on that device only. When nothing was running, there is
no notice.

## Turning it off

**Settings › Agent › Resume after a restart** is on by default. Turned off,
every run a restart cuts off waits for you with **Resume**. Only the computer
running PrismaLens can change it; a paired device shows it but can't switch it.

## Which agents keep their session

| Agent | How the run carries on |
| --- | --- |
| Claude Code, Codex, OpenCode | The agent reopens the same session. Its own record shows the cut-off command as interrupted. |
| Gemini CLI, Deep Agents | A fresh session, handed the run's conversation from PrismaLens's record. Tool output past the handoff's budget stays in `.prismalens-handoff/transcript.md` in the workspace. |

<Aside>
The session lives with the agent, on the computer that runs PrismaLens. When
the agent no longer has it, the run carries on in a fresh session handed the
conversation, and the message says so.
</Aside>
