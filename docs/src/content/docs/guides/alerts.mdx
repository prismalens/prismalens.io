You can always write an incident by hand. To have incidents open on their own,
point Prometheus Alertmanager at PrismaLens.

What happens then:

- A **firing** alert becomes an alert. Its identity is its label set, the way
  Alertmanager fingerprints it: two firings that differ in any label are two
  alerts, and the same label set firing again counts as a repeat.
- The alert reaches a **service** through a `service` label whose value equals
  the service's name exactly. Nothing else maps an alert to a service.
- The alert joins an open incident that already carries an alert with the same
  title and text, whatever its labels; otherwise it opens a new incident.
- Only the alert that **opens** an incident decides whether an investigation
  starts. A critical or high alert on a service starts one on arrival; change
  that per service under **Services → the service → Investigation** (always,
  critical and high, critical only, never). A new incident with no service
  runs nothing. Whenever the answer is no, the incident's **Timeline** says
  why and where to change it.
- A **resolved** alert resolves its alert, and resolves the incident once none
  of its alerts are still firing.

## The webhook token

The first `pl up` generates a token and saves it in your workspace:

```text
~/.prismalens/PRISMALENS_WEBHOOK_SECRET_FILE
```

Every delivery must carry it. A delivery without it gets `401`, and a wrong one
gets `403`. `pl doctor` shows the file's path and never prints the token.
PrismaLens reads the file when it starts, so if you replace the token, restart
`pl up` and update every sender.

## Configure Alertmanager

Add a receiver that sends to PrismaLens and reads the token from the file:

```yaml
receivers:
  - name: prismalens
    webhook_configs:
      - url: http://127.0.0.1:3001/api/webhooks/prometheus
        send_resolved: true
        http_config:
          authorization:
            type: Bearer
            credentials_file: /home/you/.prismalens/PRISMALENS_WEBHOOK_SECRET_FILE
```

Then route the alerts you care about to the `prismalens` receiver.

PrismaLens accepts 20 deliveries a second and 600 a minute. Keep Alertmanager's
grouping on so a burst arrives as a few grouped deliveries.

## Try it with curl

```bash
TOKEN=$(cat ~/.prismalens/PRISMALENS_WEBHOOK_SECRET_FILE)
curl -s -X POST http://127.0.0.1:3001/api/webhooks/prometheus \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"version":"4","status":"firing","alerts":[{"status":"firing","labels":{"alertname":"HighErrorRate","severity":"critical","service":"payments"},"annotations":{"summary":"5xx above 5% for 10 minutes"},"startsAt":"2026-09-13T10:00:00Z","fingerprint":"abc123"}]}'
```

```text
{"received":1,"processed":1,"alertIds":["d0783551-1a41-4185-8414-a64cfc33519e"]}
```

With a service named `payments` that has a repository, that one call opens an
incident, starts an investigation and puts the report on the incident page.
Without the `service` label the incident opens with no service and the
Timeline says nothing ran.

Senders that cannot set a header can sign the body instead: send
`X-Hub-Signature-256: sha256=<hex>`, the HMAC-SHA256 of the exact body bytes
keyed with the token.

## When Alertmanager runs on another machine

PrismaLens listens on `127.0.0.1`, so only the same machine can reach it. To
accept alerts from elsewhere on your network, start it on all addresses:

```bash
pl up --host 0.0.0.0
```

PrismaLens warns when it binds beyond loopback, and the app then serves plain
HTTP without TLS, so do this only on a network you trust. If you reach it by a
hostname rather than an IP address, add that name to `PRISMALENS_ALLOWED_HOSTS`.

**Alertmanager in Docker on Linux** cannot reach `127.0.0.1` on the host. Start
PrismaLens with `--host 0.0.0.0` and use the host's IP address in the receiver
URL, or run the Alertmanager container with `network_mode: host`.

<Aside type="caution" title="A laptop misses alerts while it sleeps">
A webhook needs PrismaLens running and reachable when the alert fires.
Alertmanager does not retry a refused connection on its own. It sends the
alert again only with the group's next notification, by default up to 4 hours
later while the alert keeps firing. An alert that fires and resolves while
your laptop is closed never arrives. Write the incident by hand for anything
you missed.
</Aside>
