PrismaLens has no accounts. A browser gets in by opening a one-time pairing
link, which only someone at the host machine can produce. No address grants
access by itself, not even `localhost`.

## The machine running `pl up`

`pl up` prints a link and opens your browser on it:

```text
✔ PrismaLens is ready at http://localhost:6473
ℹ For a machine that should always be on: pl service install
ℹ Open: http://localhost:6473/pair#9f1c…
ℹ It works once, for 15 minutes; treat it as a password. `pl pair --operator` prints another.
```

The page pairs as soon as it opens and lands on your incidents. That browser
keeps its session, so the next `pl up` needs no link. Pass `--no-open` to
print the link without opening a browser.

If the link has expired, or you want this machine's session in a second
browser, print another one on the host:

```bash
pl pair --operator
```

## A phone or a second computer

Reach the box over [Tailscale](https://tailscale.com): a phone or laptop
signed in to the same tailnet reaches it from anywhere, over HTTPS, with
nothing exposed to the internet. On the host:

```bash
pl up --tailscale-serve
pl pair --tailscale --label "phone"
```

Open the link on that device within 15 minutes. It works once. Devices are
named `<link label> · <browser> on <OS>`, e.g. "This machine · Firefox on Linux".
The device then appears under **Settings → Devices**, where you can revoke it. A
paired device stays valid until revoked (the cookie renews on use). It can read
and run investigations. Only this machine's own session can pair or revoke
devices.

Without `--tailscale` or `--address`, the link points at `localhost`, which
reaches only the host itself, and `pl pair` says so.

## Reaching it over a tailnet

[Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve) puts
HTTPS in front of the app and keeps it on your tailnet. PrismaLens stays
bound to `127.0.0.1`. You need the `tailscale` command logged in on the box,
with MagicDNS and HTTPS certificates turned on for the tailnet, and the
Tailscale app on each device you pair.

```bash
pl up --tailscale-serve
```

```text
✔ PrismaLens is ready at http://localhost:6473
✔ On your tailnet: https://box.tail1234.ts.net
ℹ Pair a device there with `pl pair --tailscale`.
```

For that run, PrismaLens:

1. reads this machine's name from `tailscale status --json`,
2. adds it to `PRISMALENS_ALLOWED_HOSTS`, so requests for it aren't refused,
3. runs `tailscale serve --bg --https=443 http://127.0.0.1:6473`, unless that
   mapping already exists. If port 443 already serves something else, it stops
   and tells you instead of replacing it.

`pl pair --tailscale` sets up the same mapping if it is missing, but the server
must already allow the tailnet name: start it with `--tailscale-serve`, or with
`PRISMALENS_ALLOWED_HOSTS` set to the name. To keep it across restarts, install
the background service with the flag:

```bash
pl service install --tailscale-serve
```

| Error | What to do |
| --- | --- |
| `tailscale` isn't on PATH | Install Tailscale and log in. |
| Tailscale is logged out | Run `tailscale up`. |
| Refused to change serve settings | Run `sudo tailscale set --operator="$(id -un)"` once. |
| Serve is not enabled on your tailnet | Open the link Tailscale prints and enable it. |

To set it up by hand instead, run `tailscale serve --bg 6473` and start
PrismaLens with the name allowed and the public address set, which also marks
the session cookie `Secure`:

```bash
PRISMALENS_ALLOWED_HOSTS=box.tail1234.ts.net \
PRISMALENS_PUBLIC_URL=https://box.tail1234.ts.net \
pl up
```

## Any other address

If the device reaches the host some other way, such as your own reverse
proxy, name that address:

```bash
pl pair --address https://prismalens.example.internal --label "laptop"
```

`pl pair --address <url>` checks the address first and refuses when it's
unreachable, when the host isn't allowed (it prints the
`PRISMALENS_ALLOWED_HOSTS=<host>` line to add), or when another PrismaLens
answers.

Pairing over a plain LAN address works too, after `pl up --host 0.0.0.0`, but
we don't recommend it:

- Over plain HTTP, the pairing link and the session cookie cross the network in
  clear.
- Browsers allow clipboard access only over HTTPS, so the app's copy buttons
  do nothing.
- The host's firewall decides whether the device gets through. Under WSL2, LAN
  traffic doesn't reach WSL until Windows is set up for it; see
  [WSL networking](https://learn.microsoft.com/en-us/windows/wsl/networking).

<Aside type="caution" title="What this does not do">
PrismaLens is built for one person's machine. It has no users or roles, and
anyone holding a paired device can read every incident and run
investigations. Pair only devices you control, and revoke a device you lose
under **Settings → Devices**.
</Aside>
