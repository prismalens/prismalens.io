The **Conversation** tab on an incident shows what the agent says and the
tool calls it makes, with one box at the bottom to write to it. The box
changes with the run, so what Enter does depends on where the run is.

## Investigate or Ask

An incident holds two kinds of thread, and both show in the sidebar under the
open incident:

- An **investigation** gathers the alert and the code, then works toward one
  report. It is always named **Run #N**.
- A **chat** is a question to the agent. It writes no report, and ends as
  **Ended**, or **Error** when it fails.

Where both make sense, a chip in the box says which one your next message
asks for: **Investigate** or **Ask**. Enter and the send button do what the
chip says.

## What the box does

| The thread is | The box says | Sending |
| --- | --- | --- |
| A new run, set to Investigate | **Brief the agent (optional)** | **Investigate** starts an investigation, with your text as its brief. |
| A new run, set to Ask | **Ask about this incident** | Starts a chat. Text is required. |
| Working | **Message the agent** | Sends a message to the running agent. |
| Stopped or failed before its report | **Say what to change, or just continue** | **Investigate** continues it to its report. **Ask** asks a question and leaves the run as it was. |
| An investigation that wrote its report | **Ask about this run** | Asks a question in the same session. The report stays as it is. |
| A chat | **Continue this chat** | Asks the next question in the same chat. |
| A run whose session cannot reopen | "This run can't continue. Start a new run." | **New run** opens a new draft. |

A new run starts set to Investigate when the incident has alerts and no
report yet, and set to Ask otherwise. **New run**, under the incident's
**More actions** or under its runs in the sidebar, opens a new draft.

The line under the box says how the run started (**Started by the alert** or
**Started by you**) and, while it works, what it owes: **Working toward a
report** or **Working on an answer**. When your last question did not get an
answer, it says **Last message: stopped by you** or **Last message: error**.

## A message while the agent works

A message goes to the agent's own session, so the agent answers it as part of
the same investigation.

- **Enter**, or the send arrow, queues the message. The agent reads it at its
  next pause. The box shows `N waiting` while any are queued.
- **Ctrl+Enter** (**Cmd+Enter** on macOS), or **Send now**, ends the agent's
  current step and delivers the message at once, after any messages still
  waiting, in the order you sent them. Anything that step had begun is lost.
- **Shift+Enter** starts a new line.

A message can hold up to 4000 characters. Under **You**, each message shows
where it is: **Waits for the next pause**, **Sent now**, **Delivered at the
next pause** or **Not delivered**.

If the run ends before the message reaches it, the box says so and **Save as note** keeps the text on the incident's
Timeline. A message sent before the agent has started is refused with `The run
has not started yet; try again shortly.` The API answers both with `409
Conflict`.

## Stop

**Stop** in the box ends the run. **Esc** does the same while the cursor is in
the box and the agent is working. The state reads **Stopping**, then **Stopped
by you**, which is not a failure. To go on, see
[Resolving and reopening incidents](/guides/incident-lifecycle/#stop-then-continue).

## After the run ends

What you can send after a run depends on how it ended:

| The run | Investigate | Ask |
| --- | --- | --- |
| Stopped by you, or failed, before its report | Continues the same session to its report | Answers in the same session; the run keeps its state |
| Wrote its report | Not offered here; use **Investigate again** | Answers in the same session on the same code; the report stays as it is |
| Its session cannot reopen | **New run** | **New run** |

A question on a finished run rebuilds the run's copy of the repository at the
commits it read. If the session cannot be reopened, the message is refused
with the reason. deepagents cannot reopen a finished session, so after a run
its box offers **New run**.

**Investigate again**, under a finished report, opens a new run whose brief
holds what you typed in the box and any files you attached, then the report
quoted, for example:

```text
Re-check Run #1. It found: The p99 rise follows deploy 9f3c1a. Cause named: The cache TTL dropped to 1s. Next steps it proposed: Restore the TTL; Add a cache hit-rate alert.
```

Edit the brief before you send it. The first report stays as it is.

One thread works on an incident at a time. While one works, the box on any
other thread or a new run says, for example, `Run #2 is working; message it or
stop it`.

Only one question runs at a time. A second one gets `A follow-up is already
running.`, and a message of the wrong kind for a working run gets, for
example, `Run #2 is working on an answer; wait or stop it`.

## Attachments

Attach a file with the paperclip, by pasting it, or by dropping it on the box.
A message takes up to **5 files**.

| Kind | Types | Limit |
| --- | --- | --- |
| Image | PNG, JPEG, WebP, GIF | 4 MB each |
| Text | `.log`, `.json`, `.csv`, `.md`, `.txt`, `.yaml`, `.yml`, or any `text/*` type | 256 KB each |

PrismaLens checks the bytes, not the file name or the type your browser
sends: an image must be one of the four image formats and a text file must be
UTF-8.

- Text goes to the agent inside the message, fenced as data and named by the
  file. Text in it is evidence the agent reads, not instructions it follows,
  and the agent marks anything it took from it as **inferred** unless a
  command it runs shows the same thing.
- An image goes only to an agent that says it reads images. The agent's check
  records that answer. The paperclip says `Images: not checked yet` until
  the check has run, and the box takes text files only. Run it with **Settings
  → Agent → Check readiness**. An agent that cannot read images says so and
  takes text only.
- Files are stored in your PrismaLens workspace, outside the copy of the
  code the agent reads. The agent sees only what the message carried.

Attachments can ride on the brief that starts a run, on a message, on a
continue and on a follow-up.

## Model and effort

Before a run starts, the box carries three controls next to the paperclip:
the **agent and model picker**, the **access level** and, when the agent
offers one, **effort**. The model list starts with **Agent default**, which
names the model the agent reported using. A choice in the box applies to that
run only and never changes Settings. The defaults for the next run live in
**Settings → Agent**, which has an **Effort** row too. Once a run starts, the
box shows the agent, model and access level it is fixed on, and changing one
of them opens a new run that is the same run with that one change. A follow-up
uses the model its run used.

| Agent | Model and effort |
| --- | --- |
| OpenCode, Claude Code, Codex | Sent to the agent over ACP |
| Gemini CLI, deepagents | The agent picks its own model |

The effort control appears only when the agent's readiness check found an
effort option, and offers the agent's own values with its default marked.

After sending, PrismaLens checks the agent's answer. If the agent did not take
the model or effort, the run stops before its first prompt with the reason:
`<Agent> would not switch to <model>; it offered <its models>`, or `<Agent>
would not take <effort> effort; it offered <its values>`. A run never starts
on a different model from the one you chose, and the report's **Run** chip
names the model that ran and the effort it accepted. A model set for Gemini
CLI or deepagents is refused before the run: `<Agent> picks its own model.
Clear <model> in the picker above.`

<Aside type="note" title="Keys in the box">
Enter sends or queues, Ctrl+Enter sends now, Shift+Enter is a new line, and Esc
stops the agent while it works. The `?` key opens the full keyboard map.
</Aside>
