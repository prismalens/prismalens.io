**Incidents** opens on the **Inbox**. It lists the incidents that need you,
grouped by what each one needs, and each row carries the one action that
moves it on. The header switches between three views, **Inbox**, **All
incidents** and **Analytics**, and its **Filter** box matches an incident's
ID, title or service.

## The tiles

Three tiles sit at the top. Each one is a link.

| Tile | What it says | Opens |
| --- | --- | --- |
| Getting worse | The incident with more alerts firing now than an hour ago, for example `INC-12 HighLatency`. With none, **Nothing**, and under it "Firing alerts are holding steady" or "Nothing is firing". | That incident's overview |
| Alerts | `3 firing` or **Nothing firing**, and under it how many cleared in the last day | Alerts |
| Services | `2 of 5 degraded` with their names, or `5 of 5 healthy` | Services |

Until a coding agent is set up, the third tile is **Agent: Not set up**,
"Investigations wait until one is", and opens **Settings → Agent**.

## Needs you

Every open incident that waits on you sits in one group, in this order:

| Group | An incident sits here when | The row's second line | The row's button |
| --- | --- | --- | --- |
| Waiting for your approval | A run is paused on an ask | **Waiting:** the agent asks before it runs a step | **Open**, on that run |
| Finding ready | A finished investigation named a likely cause, even when a later run failed or was stopped | **Likely:** and the cause's first clause | **Open** |
| Run failed or stopped | The newest finished run failed or was stopped, no earlier run named a cause, and none is working | **Failed:** and why, or **Stopped by you** at 14:02, after 3m | **Retry run**, plus **Resolve** when nothing is firing |
| No cause found | No run has started, or the last one ended without naming a cause | "Not investigated yet" or "The last run found nothing that explains it" | **Investigate** or **Investigate again** |
| Alerts cleared | Every alert on it cleared, and you have not resolved it | **Cleared 2h ago.** and the likely cause, "No cause named" or "Never investigated" | **Resolve**, plus **Investigate** if no run ever started |

An ask outranks everything else, and an incident whose alerts all cleared sits
in Alerts cleared whatever its runs found.

An incident with a run working and no finding yet asks nothing of you, so it
is not in Needs you; it is under [Working](#working).
A Finding ready row whose incident has a new run working says **Checking a
follow-up.** and keeps the finding.

When an alert on an **Alerts cleared** incident fires again after the refire
window, it opens a new incident (see
[What a refire does](/guides/incident-lifecycle/#what-a-refire-does)). The
old row then says **Same alert as INC-14.**, when it fired and how long it
lasted, and its button is **Merge into INC-14**. Confirming moves its alerts to
the newer incident and ends the old one as merged; its runs stay where they
are.

Each group shows five rows, then **Show N more**. With more than one group,
chips above them filter to one group, each with its count.

### A row

From left to right, a row shows:

- the severity, the ID and the title (hover for the full title), and the service;
- the second line from the table above, with a breathing dot while a run works on the incident;
- on a wide window, a line of the firing alerts over the last 24 hours;
- **Firing, worse**, **Firing, steady**, **Not firing** or **No alert**;
- how long ago it opened, such as `13h ago`;
- the button, and a menu with **Open overview**, **Investigate again**, **Resolve** and **Merge into another incident**. The menu leaves out what the button already does.

The button reads **Starting** or **Resolving** while it works. When the agent
cannot start, nothing changes and a message says **No run started** and why.
**Resolve** opens the same dialog as on the overview (see
[Resolving and reopening](/guides/incident-lifecycle/)). A row that arrives
while you watch glows once.

### Empty and loading

With nothing waiting, the group reads **Nothing needs you.**, or **Nothing
matches.** while the filter has text. While the Inbox loads, the tiles and
rows show placeholders and the sidebar's count stays blank.

Before a coding agent is set up, the Needs you slot holds one card instead:
**Set up a coding agent to investigate incidents**, with how much of setup is
done and the line "Alerts still arrive and open incidents; nothing
investigates them until an agent is set up." **Set up an agent** opens
**Settings → Agent**.

Once an agent is set up but setup is not finished, a line above Needs you says
what is missing and links to it, for example "Setup, 3 of 4 done: no service
names its code yet, so runs read nothing." with **Add a service**.

## Working

Below Needs you, a quiet list of the incidents a run is working on with no
finding yet: the ID, the title, the service, **No finding yet** and how long
the run has been going, such as `6s`. A row opens the run's transcript. When
the run reports, the incident moves to the Needs you group its finding puts it
in. The list is hidden when nothing is working.

## Recently resolved

Below Needs you, the incidents you resolved most recently, each with **Resolved
by you** or **Merged into INC-14** and how long ago. **All incidents** beside
the heading opens the All incidents view filtered to Resolved.

## All incidents and Analytics

**All incidents** lists every incident in a window (**All time**, **24
hours**, **7 days**, **30 days**, **90 days**), newest first, with filters for status
(**Open**, **Alerts cleared**, **Resolved**) and severity. Each row says where
the incident stands in the Inbox's words: its Needs you group, **Run working**,
**Open**, **Resolved** or **Merged into INC-14**.

**Analytics** charts incidents over the last 7, 30 or 90 days.

## The sidebar

The sidebar lists every incident you have not resolved, under its service.
PrismaLens groups by service: anything that alerts, such as an API, a
database, a queue or a cache. Each service heading shows its type's icon and a
health dot: **Degraded, getting worse**, **Degraded** or **Healthy** (a screen
reader hears the words).

- The incident's name opens its overview.
- Its chevron lists its runs and questions, newest first: `Run 2, likely
  cause`, `Run 1, failed`, `Ask: did v1.41 change the pool size?`. A working
  run breathes. Each opens that run's transcript or the Ask conversation.
- A service shows eight incidents, then **N more**.

**Incidents** in the sidebar carries the count of incidents that need you. A
screen reader hears it as "Incidents, 7 need you". **Settings** sits at the
bottom.

## How the incident pages link

An incident has one overview, and a page for each run and each question.

<IncidentFlow />

- From the Inbox, a row's title or the Getting worse tile opens the overview.
  So does the incident's name in the sidebar.
- The overview links to a run's transcript from **Run 2 transcript** under
  Why and from the run's name in the Latest run strip, and to the Ask
  conversation from **You asked**. The **Runs and questions** menu lists them
  all and ends with **New conversation**.
- On a transcript or an Ask, the incident's name in the breadcrumb
  (`HighLatency / Run 2`) goes back to the overview.
- The back chevron goes to the Inbox from every incident page. So does
  **Esc**, unless the cursor is in a field or a menu, a dialog or the Run
  details panel is open; Esc closes those first.
- A new conversation becomes a run or an Ask on its first send.

Links to the old Report, Alerts and Timeline tabs open the overview. A link to
a run by its own address opens that run's transcript.
