There are two ways to run PrismaLens, depending on what you need:

1. **CLI** — a single npm package you run from your terminal. No account, no
   server, bring your own model provider key. The quickest way to try
   PrismaLens.
2. **Self-hosted server** — a Docker Compose stack with a web UI, webhook
   intake, and integrations. For teams who want a shared Command Center.

## Option 1: CLI (quickest)

The `prismalens` CLI (alias `pl`) investigates a firing alert straight from
your terminal — no server required.

### Prerequisites

- Node.js 22+
- A model provider credential (BYO-key — see the [CLI overview](/cli/) for
  supported providers)

### Try it without installing

```bash
npx prismalens doctor
```

`doctor` checks that a harness binary and an LLM credential are on your
machine before you run anything.

### Install it

```bash
npm install -g prismalens
```

This gives you both the `prismalens` and `pl` commands.

Full command reference, configuration, and harness setup live under
[CLI docs](/cli/) — start there for `investigate`, `serve`, `init`, and the
`prismalens.config.yaml` reference.

## Option 2: Self-hosted server (Docker Compose)

Run the full PrismaLens stack — web UI, API, database, and webhook
endpoints for Prometheus, Grafana, and other alert sources.

### Prerequisites

- Docker Engine 24+
- Docker Compose v2+
- 2 GB RAM minimum

### Steps

```bash
git clone https://github.com/prismalens/prismalens
cd prismalens
cp .env.example .env
docker compose up -d
```

PrismaLens will be available at `http://localhost:3000`.

### Environment Variables

Configure PrismaLens by editing the `.env` file. For a minimal setup, you
only need:

| Variable | Description | Default |
|----------|-------------|---------|
| `PRISMALENS_PORT` | API server port | `3001` |
| `PRISMALENS_DB_TYPE` | Database type (sqlite or postgresql) | `sqlite` |
| `ANTHROPIC_API_KEY` | Anthropic API key (for Claude) | — |

### Health Check

Verify the installation:

```bash
curl http://localhost:3000/health
```

Expected response:

```json
{ "status": "ok" }
```

### Troubleshooting

#### Health check returns connection refused

**Symptom**: `curl http://localhost:3000/health` fails with "Connection refused"

**Cause**: The API server takes 15-30 seconds to initialize after `docker compose up`.

**Solution**: Wait 30 seconds, then retry. Check logs with `docker compose logs api`.

---

#### ANTHROPIC_API_KEY not found

**Symptom**: API server fails to start with "ANTHROPIC_API_KEY environment variable not set"

**Cause**: You didn't create a `.env` file or didn't set the API key.

**Solution**:
```bash
cp .env.example .env
# Edit .env and add your Anthropic API key
docker compose restart
```

---

#### Out of memory errors

**Symptom**: Container crashes with OOMKilled or "JavaScript heap out of memory"

**Cause**: LangGraph agents need at least 2GB RAM. Default Docker limits may be too low.

**Solution**: Check `docker stats` to verify memory allocation. Increase Docker Desktop memory limit to 4GB minimum.

---

#### Database connection errors

**Symptom**: "Unable to connect to database" errors in logs

**Cause**: PostgreSQL container not ready when API starts, or incorrect credentials.

**Solution**:
```bash
# Check PostgreSQL container is running
docker compose ps

# If postgres is down, check logs
docker compose logs postgres

# Restart services in correct order
docker compose restart postgres
docker compose restart api
```
