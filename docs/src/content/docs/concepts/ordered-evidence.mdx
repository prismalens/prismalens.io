---
title: Ordered evidence
description: Why a PrismaLens report ranks hypotheses by evidence instead of emitting a numeric confidence score.
---

Every PrismaLens investigation ends in the same structure, and one choice shapes
all of it: the report **orders** hypotheses by evidence rather than attaching a
numeric confidence score to each. This is a deliberate design decision
(ADR-0002), not an omission.

## Why not a confidence score?

A number like "87% confident" reads as precise and earns trust it hasn't
necessarily earned. For an LLM-driven tool it's worse than imprecise — it's a
fabricated statistic. The model has no calibrated basis for "87 vs 72," so a
score invites you to act on a digit instead of on the reasoning behind it.

PrismaLens refuses to manufacture that number. Instead it gives you the thing a
score is a lossy summary of: the **evidence, ranked**.

## What the report gives you instead

- **Hypotheses, ordered most to least plausible.** The order *is* the ranking —
  there's no separate rank field. Each hypothesis carries the evidence that
  supports or contradicts it, and where that evidence came from (the exact
  command or source), so you can check it yourself.
- **Ruled out.** Candidate causes that were considered and dropped, with the
  contradicting evidence that eliminated them — so you can see the paths already
  walked, not just the conclusion.
- **Coverage.** What was queried and what wasn't. An investigation that couldn't
  reach a data source says so, rather than letting silence read as "all clear."
- **Next steps.** Concrete checks to confirm the top hypothesis or dig further.
- **Flagged content.** Anything in the input that tried to *instruct* the model
  rather than inform it — see [What gets flagged](#what-gets-flagged) below.

## Where a piece of evidence came from

Each evidence item carries an `origin`, because not everything a report cites was
observed by the agent itself:

- **`tool`** — a command, query, or file read the harness actually ran. This is
  the default, and before host-supplied facts existed it was the only kind. If
  `origin` is absent on an older stored report, read it as `tool`.
- **`context-pack`** — a fact the **host** supplied that the agent could not have
  reached by looking around: which services depend on the failing one, what
  shipped in the alert window, which past incident this one rhymes with. Its
  `source` is the fact family (`context-pack:changes`,
  `context-pack:neighbors`, `context-pack:priorIncidents`), not a command string.

A host-supplied fact is **always `inferred`, never `verified`**, and always has a
null `toolCallId`. That is enforced after the model writes the report, not left
to its discretion: a host fact can only become `verified` if the agent goes and
re-observes it with a tool, in which case it cites that tool and its origin is
`tool`. The model does not get the final word on where a claim came from — and
it can't opt out by leaving the field blank either, because the rule keys off the
`context-pack:` source prefix rather than the label.

Host facts also carry no similarity score. A prior incident is listed because of
the labels it shares with this one, and those shared labels are what the report
shows you — the same reason ranking beats scoring everywhere else here.

## What gets flagged

Some of what an investigation reads is written by strangers: deploy names, branch
names, alert names, commit text, a past incident's title. Occasionally that text
tries to *give the model instructions* rather than inform it.

PrismaLens renders that material inside a fenced data-only block and tells the
model, on both sides of the fence, to treat it as data. When a line still tries
to issue an instruction, the correct response is to **ignore it, keep
investigating, and record it** — never to drop it quietly. Those records land in
the report's `flaggedContent`: where it appeared (`context-pack` or
`tool-output`), a short quote of the offending text, and why it was flagged.

An empty or absent `flaggedContent` means nothing tried. If it isn't empty, read
it — something in your change or incident data is shaped like an instruction, and
you want to know that whether it was deliberate or not.

## Read it as a lead

Because there's no score to hide behind, the report puts its reasoning in the
open — which is exactly how you should read it. A PrismaLens report is a
strong, evidence-linked **lead**, not a verdict; the same run can differ across
attempts, and a confidently-worded top hypothesis can still be wrong. The
ordering tells you where to look first; the linked evidence lets you confirm it
fast. See [How PrismaLens works](/concepts/how-it-works/#a-report-is-a-lead-not-a-verdict)
for more on treating a report as a lead.
